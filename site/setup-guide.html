Configuration guide

Set up the two service principals

The app uses an Admin service principal for discovery and direct-access auditing, and a test service principal for SQL and OneLake data-path validation.

1. Configure API access

Test service principalCreate a service principal for testing purposes, with the following API permissions. Setup is done on Azure portal.
Admin service principalCreate a service principal admin for auditing user permissions, with the following API permissions. Setup is done on Azure portal.Ensure the Admin SP is added to a security group that is allowed to access read-only Admin APIs. This setting is found in Fabric Admin Portal permissions.
Control plane permissions

2. Grant direct item access

For least-privilege permissions, ensure no workspace role is given to the user.

Open Manage permissionsRight-click on the respective Lakehouse and open Manage permissions > Add user.
Grant Read accessGrant the test user Read access on the Lakehouse. Do not tick any other boxes when aiming for a least-privilege setup.
Data plane permissions

3. Configure OneLake ABFS access

Direct OneLake ABFS validation uses the test service principal’s OneLake security role and data scope.

Open OneLake security
Review DefaultReaderCheck the automatic DefaultReader role assignment before testing restricted access. Make sure your restricted user is not assigned to this role.
Create a new, restricted role
Restrict data scope for the new role
Add the test identity as a member in the new role
OneLake roles control ABFS data access. Item Read access alone does not grant access to every table path.
Data plane permissions

4. Configure SQL permissions

SQL endpoint visibility and query behavior are controlled by the Lakehouse SQL analytics endpoint mode and SQL security grants.

Grant table permissionsOpen a SQL endpoint query and grant only the table permissions required by the test identity.
Apply row-level securityUse row-level security when the identity should see only a subset of table rows.
Apply column-level securityUse column-level security when selected columns must be hidden from the identity.
The SQL and ABFS tabs test separate data paths. Validate each path after changing permissions.
